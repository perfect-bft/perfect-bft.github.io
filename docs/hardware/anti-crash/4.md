## 什么是视频虚拟线圈防砸

:::tip
**视频虚拟线圈**（也叫视频检测区、虚拟地感）不依赖任何硬件传感器，而是在相机的实时画面上**用鼠标画一个或多个检测区域**，由相机或平台的 AI 算法持续分析该区域内的像素变化。

区域内出现车辆、行人、非机动车时，算法判定"有障碍"，输出信号给道闸主板禁止落杆。

**本质：用算法替代了地感线圈的硬件。**
:::

## 工作原理

| 步骤 | 说明 |
|------|------|
| 1 | 相机实时采集车道视频流（一般 25fps） |
| 2 | 在画面上划定检测区域（矩形 / 多边形 / 线条） |
| 3 | 算法对区域内图像做**背景建模**，建立"没有车时"的参考底图 |
| 4 | 逐帧比对当前画面与背景模型，计算差异像素比例 |
| 5 | 差异超过阈值且满足目标特征（尺寸、形状、运动方向）→ 判定有目标 |
| 6 | 输出 IO 信号 / 网络指令给主板 |

:::info
高级算法会叠加**深度学习车辆/行人检测模型**，不只靠像素差分，而是真正"认出"画面里的是一辆车还是一个人，抗干扰能力更强。
:::

## 三种实现方式

| 方式 | 实现位置 | 优点 | 缺点 |
|------|----------|------|------|
| **相机内置** | 车牌识别相机自身算法 | 响应最快、不依赖网络 | 需要相机固件支持，老型号没有 |
| **平台侧** | 云端/服务器分析视频流 | 可远程配置、算力强 | 依赖网络，断网即失效 |
| **NVR / 边缘盒子** | 本地录像机或 AI 盒子 | 断网可用、可管多路 | 需额外设备投入 |

:::warning[防砸必须本地化]
**防砸是安全功能，绝不能依赖云端。** 网络延迟、断网、服务器宕机都会导致防砸失效。

用于防砸的视频检测必须跑在**相机本地或本地边缘设备**上，云端分析只能做统计和告警。
:::

## 检测区域绘制规则

### 划在哪里

:::tip
- **位置**：道闸杆正下方地面区域，向车辆驶来方向延伸 2~4m
- **形状**：梯形（近大远小）比矩形更贴合透视，检测更准
- **宽度**：完整覆盖车道宽度，两侧各留 10~20cm 余量
- **高度**：从地面往上覆盖到车辆引擎盖高度即可，**不要画到天空**，否则云、飞鸟、树枝晃动都会误报
- **数量**：可画 1~2 个，主检测区 + 辅助确认区
:::

### 常见错误画法

:::danger
- **画得太靠上（涵盖天空）**：光影变化、云彩飘动 → 频繁误报
- **画到相邻车道/人行道**：旁边过人过车 → 杆一直不落
- **画进闸杆运动轨迹**：闸杆本身被当成目标 → 杆永远不落
- **画得太小（只覆盖车牌位置）**：车辆前后部分在框外，车没完全通过就判定为空 → 砸车
- **画在强反光地面**：雨后地面积水反光 → 误报
:::

## 与硬件方案的对比

| 维度 | 地感线圈 | 红外对射 | 毫米波雷达 | **视频虚拟线圈** |
|------|----------|----------|-----------|----------------|
| 硬件成本 | 低 | 低 | 中高 | **零** |
| 施工成本 | 高（破路） | 中 | 低 | **零** |
| 防汽车 | 优 | 优 | 优 | 良 |
| 防行人/非机动车 | 差 | 优 | 优 | 优 |
| 夜间效果 | 优 | 良 | 优 | **依赖补光灯** |
| 逆光/强光 | 优 | 差 | 优 | **差** |
| 雨雾雪 | 优 | 差 | 优 | **差** |
| 检测静止目标 | 优 | 优 | 优 | 优 |
| 依赖算力 | 否 | 否 | 否 | **是** |
| 改造难度 | 高 | 中 | 低 | 最低 |

:::warning[定位：补充方案，不是唯一方案]
视频虚拟线圈**不建议单独使用**作为唯一防砸手段。原因是它受光照、天气、镜头脏污影响大，属于**软件级**检测，可靠性低于硬件传感器。

推荐定位：
- **已有相机、预算敏感、不便施工**的场合 → 可作为**主防砸**
- 标准车场 → 作为地感/雷达之外的**第二道冗余**
- 人车混行 → 视频检测行人的能力很强，是很好的**补充**
:::

## 启用条件检查

:::tip
上方案前先确认：
1. **相机是否支持**：进相机 Web 后台/客户端，看是否有"视频检测""虚拟线圈""IO 输出"相关菜单
2. **补光灯是否够**：夜间防砸依赖清晰画面，必须保证车道有足够照度（一般要求补光灯打开且亮度足够）
3. **算力是否够**：部分低端相机开了视频检测后，车牌识别率会下降，需实测确认
4. **WDR 是否开启**：出入口逆光严重，必须开宽动态
5. **镜头是否干净**：泥点、雨滴、蜘蛛网会直接导致误报
:::

## 配置步骤（通用流程）

不同品牌菜单位置不同，但流程基本一致：

1. 登录相机 Web 管理页面（浏览器输入相机 IP）
2. 进入「智能分析」/「事件检测」/「视频检测」菜单
3. 启用检测功能，选择检测类型（**车辆**、**行人**、**运动目标**）
4. 在实时画面上**绘制检测区域**（拖拽多边形顶点）
5. 设置**灵敏度**（建议先设中等，实测后微调）
6. 设置**目标最小尺寸**（过滤小动物、飘落物）
7. 设置**保持时间**（车辆离开后信号延迟释放，一般 1~3s）
8. 配置**输出方式**：IO 输出（接主板）/ 网络告警（接平台）
9. 保存并**实测验证**

:::warning[必须实测的四种情况]
1. 车辆正常通过 → 杆应正常抬起、车过后落下
2. 车辆停在杆下不动 → 杆应**保持抬起不落**
3. 行人从杆下走过 → 杆应**保持抬起不落**
4. 空车道无干扰 → 杆应**正常落下**，不应长时间不落

四种全部通过才算配置合格。
:::

## 常见故障排查

| 现象 | 可能原因 | 处理方法 |
|------|----------|----------|
| 无车时杆一直不落 | 检测区内包含闸杆、树枝、光影变化 | 重画检测区，避开固定干扰物 |
| 无车时杆一直不落（夜间） | 补光灯下的飞虫、雨雪、光晕 | 提高目标最小尺寸、降低灵敏度 |
| 有车在杆下仍然落杆 | 检测区没覆盖到 / 灵敏度太低 | 扩大检测区、提高灵敏度 |
| 相机开了检测后识别率下降 | 算力不足 | 降低帧率/分辨率，或改用硬件传感器 |
| 相机镜头脏导致误报 | 泥水、蛛网、雨滴 | 定期清洁镜头，加防雨罩 |
| 逆光时段误报多 | 强光导致画面过曝 | 开宽动态 WDR、调整相机角度、加遮阳罩 |
| 检测功能菜单找不到 | 固件版本不支持 | 升级固件，或加独立视频检测器 |

:::tip[判断是算法问题还是硬件问题]
在相机后台看**实时画面**：

- 如果人眼在画面里都**看不清**车/人（太暗、过曝、有遮挡）→ 是**环境和补光问题**，先解决照明
- 如果人眼看得清但算法不报 → 是**参数问题**，调灵敏度和检测区
- 如果画面干净无目标但算法乱报 → 是**干扰源问题**，重画检测区或降低灵敏度
:::

## 补充：视频检测还能做什么

:::info
同一套视频检测能力，除了防砸还可以复用：
- **车辆存在检测**（替代地感触发抓拍）
- **车位状态检测**（路内停车、车位引导）
- **车道事件检测**：跟车、逆行、滞留、抛洒物
- **非机动车检测**：电动车闯入、未戴头盔识别
- **人流统计**

所以一旦相机支持视频检测，**性价比非常高**——一次投入，多个功能复用。
:::
